# 网络协议调试助手 PRD

版本：1.0  
日期：2026-09-03  
状态：评审稿  
适用模块：工业协议调试 / TCP、UDP、Modbus TCP 工作台

## 产品结论

网络协议调试助手必须围绕“长连接会话 + 可解释的字节转换 + 有序收发证据”设计，而不是围绕一次请求设计。用户应能同时运行 Server 和 Client，使用文本、十六进制、Base64 或文件构造报文，明确选择字符编码与消息边界，并在同一时间线上查看每一次连接、发送、接收和断开。

当前截图中的 `十六进制数据长度必须为偶数` 并非单纯校验问题：用户输入 `aaa` 时，产品仍停留在 HEX 模式，但界面没有解释“报文输入形态”和“文本字符编码”的区别，也没有在发送前给出可修复建议。这是本 PRD 的首要问题。

## 目标与边界

### 产品目标

- 支持可长期运行的 TCP Client、TCP Server 和 UDP 会话，不因一次发送自动断开。
- 正确发送和接收 ASCII、UTF-8 中文及常见地区编码，字节转换可预览、可验证。
- 支持 TCP 流的分包、粘包和消息边界配置。
- Server 能管理多个客户端，并向单个客户端或全部客户端主动发送。
- 所有事件严格按发生顺序进入统一日志，可筛选、复制和导出。
- Modbus TCP 在相同会话框架下提供结构化报文编辑与 Server 内存模拟。

### 非目标

- P0 不实现漏洞扫描、口令爆破或对生产 PLC 的自动写入。
- P0 不承诺自动猜测任意私有协议；协议解析器通过后续扩展提供。
- 字符编码检测只能作为带置信度的显示建议，不能静默改变发送字节。

## 核心产品模型

界面和内部数据结构必须分离以下五个概念：

| 概念 | 用户问题 | 示例 | 是否可独立设置 |
| --- | --- | --- | --- |
| 传输层 | 数据如何到达对端 | TCP、UDP、TLS | 是 |
| 输入形态 | 编辑器中的内容是什么 | 文本、HEX、Base64、文件 | 是 |
| 字符编码 | 文本如何转换为字节 | UTF-8、ASCII、GB18030 | 仅文本模式 |
| 显示方式 | 收到的字节如何呈现 | 文本、HEX、双栏、转义 | 是，不改变原始字节 |
| 消息边界 | TCP 字节流如何切成消息 | 原始流、分隔符、定长、长度字段 | 是 |

禁止继续使用一个“报文格式”下拉框同时承担输入形态、编码和显示三个职责。

## 用户工作流

### 调试一个 UTF-8 TCP 服务

1. 新建 TCP Client 会话，填写主机和端口。
2. 点击“连接”，状态变为已连接，并记录本地/远端端点。
3. 输入形态选择“文本”，字符编码选择“UTF-8”。
4. 输入 `中文ABC`，结尾符选择 `CRLF`。
5. 字节预览立即显示 `E4 B8 AD E6 96 87 41 42 43 0D 0A` 和 11 bytes。
6. 点击“发送”，时间线依次显示 TX 和异步 RX；连接保持不变，可继续发送。

### 作为 TCP Server 调试多个设备

1. 新建 TCP Server，会话配置监听地址、端口和消息边界。
2. 自动应答选择“不应答”“Echo”或“固定应答”。
3. 启动后，客户端列表实时显示远端地址、连接时间、收发字节数和最后活动时间。
4. 选择一个客户端发送，或选择“广播全部客户端”。
5. 某客户端断开时，仅该连接变为离线，监听器和其他连接继续运行。

### 排查未知字节协议

1. 输入形态选择 HEX，允许空格、换行、`-` 和 `:` 作为视觉分隔符。
2. 编辑器逐字节着色并显示偏移；奇数半字节或非法字符在输入时定位。
3. 接收显示选择“双栏”，左侧 HEX + offset，右侧按选定编码显示文本，不可解码字节显示替换标记但保留原始数据。
4. 复制时可选择“复制原始 HEX”“复制文本”“复制转义字符串”。

## 功能需求

### P0：可用的网络调试闭环

| 编号 | 需求 | 产品行为 | 失败行为 |
| --- | --- | --- | --- |
| P0-01 | TCP 持久 Client | 独立连接、发送、断开；同一连接可重复发送 | 断线后发送按钮禁用，并显示重连操作 |
| P0-02 | TCP 多客户端 Server | 持续监听；客户端列表；单播与广播 | 单个客户端异常不能停止监听器 |
| P0-03 | 异步接收 | 无需先发送也能接收 Server 推送 | 接收线程停止时产生明确断线事件 |
| P0-04 | 文本输入 | 文本转换为字节后发送 | 编码无法表示字符时禁止发送并定位字符 |
| P0-05 | HEX 输入 | 解析空白分隔的十六进制字节 | `aaa` 提示“第 3 位缺少配对半字节”，并提供“切换到文本” |
| P0-06 | 编码选择 | UTF-8、ASCII、GB18030、UTF-16LE、UTF-16BE、ISO-8859-1 | 不允许静默回退或丢字符 |
| P0-07 | 结尾符 | 无、CR、LF、CRLF、自定义 HEX | 预览必须包含追加后的字节 |
| P0-08 | 收发双视图 | 文本、HEX、文本+HEX、转义字符串 | 解码失败不影响原始字节保存 |
| P0-09 | 顺序日志 | 全局递增序号、时间、方向、端点、长度、内容 | UI 刷新不得重排事件 |
| P0-10 | 会话保存 | 保存端点、编码、边界、应答策略和常用报文 | 不保存明文敏感内容时给出选项 |
| P0-11 | 输入即时校验 | 未发送前显示错误位置、原因和修复建议 | 校验错误不得调用后端发送 |
| P0-12 | 明确状态 | 监听中、连接中、已连接、半关闭、已断开、重连中 | 不使用“已停止”表示多个不同状态 |

### P1：专业调试效率

- 多会话标签：同时打开多个 TCP Client、TCP Server 和 UDP 会话。
- 自动重连：关闭 / 固定间隔 / 指数退避，可设最大次数。
- 周期发送：最小周期、次数、开始/暂停/停止、跳过重叠发送。
- 常用报文库：命名、分组、变量占位符、发送历史一键复用。
- 时间戳：墙上时间和单调时钟相对间隔，支持毫秒与微秒显示。
- 日志筛选：按会话、客户端、TX/RX、错误、文本内容、HEX 字节过滤。
- 日志导出：JSON Lines、CSV、纯文本；保留原始字节的 Base64 字段。
- 本地绑定：选择本地 IP / 端口、IPv4 / IPv6、TCP keepalive、NoDelay。
- TLS Client / Server：证书、私钥、SNI、证书链和忽略验证的显式风险提示。
- UDP Server：对收到数据报的源端点进行回复，维护最近端点列表。

### P2：协议工程能力

- 消息边界解析：分隔符、固定长度、空闲间隔、长度字段。
- 长度字段配置：偏移、字段宽度、大小端、是否包含头部、长度修正值。
- 结构化模板：字段名称、类型、长度、大小端、校验和、实时解析树。
- 脚本钩子：发送前处理、接收后解析；默认隔离执行并限制运行时间。
- PCAP / PCAPNG 导入导出与 Wireshark 联动。
- WebSocket、MQTT、HTTP、串口与 TCP/UDP 转发复用同一会话模型。
- 可安装协议插件，但插件不能绕过原始字节日志。

## 字符编码与编辑器规格

### 输入模式

| 模式 | 编辑内容 | 编码控件 | 即时预览 |
| --- | --- | --- | --- |
| 文本 | Unicode 字符 | 必须显示 | 编码后的 HEX、字节数、字符数 |
| HEX | 字节的十六进制表示 | 隐藏 | 规范化 HEX、字节数 |
| Base64 | Base64 文本 | 隐藏 | 解码后的 HEX、字节数 |
| 文件 | 文件原始字节 | 隐藏 | 文件名、大小、前 256 字节预览 |

### 编码策略

- 默认文本编码为 UTF-8，无 BOM。
- ASCII 采用严格模式；输入中文时禁止发送，并建议切换 UTF-8 或 GB18030。
- GBK 在 UI 中显示为“GBK（GB18030 兼容）”，内部优先使用 GB18030 完整映射。
- UTF-16 必须显式区分 LE / BE；BOM 作为独立开关。
- 解码接收数据时，永远保存原始字节；文本视图只是一种投影。
- “自动检测”仅用于接收显示，必须显示候选编码和置信度，用户确认前不改变会话配置。

### 转义与快捷输入

- 文本模式提供“解析转义字符”开关，支持 `\r`、`\n`、`\t`、`\\`、`\xNN`、`\uNNNN`。
- 关闭该开关时，反斜杠按普通字符发送。
- 结尾符独立配置，避免用户在正文中手工维护换行。
- HEX 编辑器支持粘贴 `0x01, 0x03`、`01-03`、`01:03`，规范化后再发送。

## TCP 消息边界

TCP 是字节流，UI 不得把一次 `read()` 等同于一条完整消息。

| 模式 | 适用场景 | 配置 |
| --- | --- | --- |
| 原始流 | 人工观察、未知协议 | 每次读取作为片段，标记为 chunk |
| 分隔符 | 文本协议、行协议 | CRLF / LF / 自定义 HEX，是否保留分隔符 |
| 固定长度 | 固定帧设备 | 每帧字节数 |
| 长度字段 | 二进制协议 | 偏移、宽度、端序、修正值、最大帧长 |
| 空闲间隔 | 传统设备、RTU over TCP | 静默毫秒数，达到后提交一帧 |

原始流模式的日志用 `chunk`，经过边界解析后用 `frame`，不得混称“报文”。

## 界面信息架构

```text
┌ 会话标签 / 新建会话 / 导入配置 / 导出日志 ┐
├ Server ───────────────┬ Client ──────────────┤
│ 监听配置与应答策略     │ 远端、本地绑定与连接状态 │
│ 客户端连接列表         │ 输入模式、编码、结尾符   │
│ 单播 / 广播编辑器      │ 发送编辑器与字节预览     │
│ Server RX/TX           │ Client TX/RX            │
├────────────── 全局顺序时间线 ────────────────┤
│ #104 12:00:01.024 CLIENT TX 11 B UTF-8 ...   │
│ #105 12:00:01.026 SERVER RX 11 B UTF-8 ...   │
└──────────────────────────────────────────────┘
```

关键交互规则：

- 输入模式切换时不偷偷重解释内容；先展示转换预览，再由用户确认。
- 连接期间修改主机或端口时，显示“配置已修改，重连后生效”。
- Server 运行期间修改监听地址或端口时，要求显式重启监听器。
- 自动应答与 Server 主动发送是两个独立能力。
- 下拉框、弹出层和选项必须使用应用主题色，深色主题不得出现白底白字。
- 错误提示靠近发生位置；顶部错误条只显示影响整个会话的错误。

## 数据与技术约束

### 会话状态

每个会话至少保存：

```json
{
  "id": "session-uuid",
  "transport": "tcp",
  "role": "client",
  "connectionState": "connected",
  "inputMode": "text",
  "textEncoding": "utf-8",
  "displayMode": "dual",
  "framing": { "type": "delimiter", "delimiterHex": "0D 0A" },
  "localEndpoint": "192.0.2.10:53000",
  "remoteEndpoint": "192.0.2.20:9000"
}
```

### 事件顺序

每个事件在后端生成，不依赖前端到达顺序：

```json
{
  "sequence": 105,
  "timestamp": "2026-09-03T13:30:01.026+08:00",
  "monotonicUs": 34892342,
  "sessionId": "session-uuid",
  "connectionId": "connection-uuid",
  "direction": "rx",
  "kind": "frame",
  "bytesBase64": "5Lit5paHQUJDDQo=",
  "byteLength": 11
}
```

- 原始字节是事实来源；HEX 和文本在前端或导出层按配置派生。
- 后端对同一连接使用单调递增序号，前端按序号合并异步事件，防止 TX/RX 竞态覆盖。
- UI 只保留可配置数量的热日志；完整日志流式写盘，避免长时间运行导致内存增长。

| 指标 | P0 目标 |
| --- | --- |
| 单会话持续运行 | 24 小时无异常退出 |
| TCP 并发客户端 | 100 个连接保持可操作 |
| 日志 UI 容量 | 10 万事件时滚动和筛选仍可响应 |
| 单帧大小 | 默认 1 MiB，可配置上限 64 MiB |

## 错误设计

错误信息必须包含“发生了什么、哪一项有问题、如何修复”。

| 场景 | 不合格提示 | 合格提示 |
| --- | --- | --- |
| HEX 奇数长度 | 十六进制数据长度必须为偶数 | 第 3 个 HEX 字符 `a` 缺少配对半字节；补全为两位，或切换到“文本”模式 |
| ASCII 输入中文 | 编码失败 | ASCII 无法表示第 1–2 个字符“中文”；请选择 UTF-8 或 GB18030 |
| 端口占用 | 绑定失败 | `127.0.0.1:1502` 已被占用；显示占用进程（可获取时）并允许修改端口 |
| 未连接发送 | 发送失败 | TCP Client 尚未连接；先连接 `host:port` 后再发送 |
| 对端断开 | 接收失败 | 对端已关闭连接；保留日志并提供“重新连接” |

## 验收标准

### P0 必过场景

1. 文本模式选择 UTF-8，发送 `中文ABC` + CRLF，发送预览必须为 `E4 B8 AD E6 96 87 41 42 43 0D 0A`，对端收到 11 bytes。
2. 文本模式选择 ASCII，输入 `中文` 时发送按钮禁用，错误精确指出不可编码字符，并可一键切换 UTF-8。
3. HEX 模式输入 `aaa` 时不调用后端；编辑器定位第 3 位并建议补齐或切换文本。
4. TCP Client 建立一次连接后连续发送 100 帧，远端端口不变化，无丢帧、乱序或自动断开。
5. TCP Server 同时连接 3 个 Client，向其中 1 个单播时其他 Client 不收到；广播时 3 个 Client 都收到。
6. Server 在 Client 未发送数据时主动推送，Client 必须即时显示 RX。
7. Echo 模式下，Server RX 原始字节与 Server TX 原始字节完全相同；文本显示不参与判断。
8. 不应答模式下，Server 仍记录 RX，但不会生成 TX 事件。
9. 固定应答使用 UTF-8 中文时，按设置编码生成字节并由 Client 正确显示。
10. TCP 流拆成两次到达时，分隔符模式只生成一条完整 frame；原始流模式生成两个 chunk。
11. 断开一个 Client 后，Server 继续监听，其他 Client 不受影响；停止 Server 后所有关联连接关闭。
12. 全局日志按后端序号稳定呈现，异步 RX 不得被稍后返回的 TX 状态覆盖。
13. 深色主题展开所有下拉框时，选项文字与背景对比清晰，无白底白字。
14. 运行 24 小时后 UI 仍可切换会话、过滤日志和停止服务。

### 发布门槛

- P0 14 个场景全部自动化或半自动化通过。
- Windows x64 便携版通过真实双进程互连测试，而不仅是进程内单元测试。
- Linux 与 macOS 打包后至少完成 TCP Client / Server、UTF-8 中文、日志导出冒烟测试。
- 不允许以“一键闭环成功”代替持久连接、多客户端和字符编码验收。

## 迭代计划

| 阶段 | 范围 | 完成定义 |
| --- | --- | --- |
| M1 会话内核 | TCP 持久连接、多客户端 Server、异步 RX、顺序事件 | P0-01～03、09、12 通过 |
| M2 字节编辑器 | 文本/HEX/Base64、编码、结尾符、双视图 | P0-04～08、11 通过 |
| M3 帧与证据 | TCP 边界、日志保存/导出、长稳测试 | P0-10、性能指标通过 |

建议先完成 M1 + M2，再继续扩充工业协议数量。若字节、编码、连接和事件顺序不可靠，增加更多协议只会放大基础问题。
